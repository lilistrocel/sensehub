# Mosquitto broker (field-device MQTT)

`sensehub-mosquitto` (eclipse-mosquitto 2.0, `docker-compose.yml` service `mosquitto`) runs with
`network_mode: host` and listens on the host's **0.0.0.0:1883**: LAN `192.168.1.100:1883`, and the
tailnet. Plain MQTT, no TLS, LAN only. Do not port-forward 1883 on the router or route it through cloudflared.

| File | Committed | Purpose |
|---|---|---|
| `config/mosquitto.conf` | yes | listener, `allow_anonymous false`, persistence, size limits, stdout logging |
| `config/acl` | yes | per-user topic ACL (anything not granted is denied) |
| `config/passwd` | **no** (gitignored) | hashed passwords, generated by `gen-passwd.sh` |
| `data/`, `log/` | **no** (gitignored) | retained messages and sessions (`mosquitto.db`); log dir is spare, since logs go to `docker logs` (rotated 3 x 5 MB) |

## Users

| User | Password (in project `.env`) | ACL |
|---|---|---|
| `farm1021` | `MQTT_DEVICE_PASSWORD` | readwrite `farm/1021/#`, which covers its LWT on `farm/1021/status` |
| `sensehub` | `MQTT_PASSWORD` (passed to the backend) | read `farm/#`. It cannot publish, so the ingest can never command a device. |

## Setup / rotate passwords

```bash
mkdir -p mosquitto/data mosquitto/log           # must be owned by uid 1000 (the container user)
./mosquitto/gen-passwd.sh                        # creates missing passwords in .env, writes config/passwd (0600)
docker compose up -d mosquitto
docker kill -s HUP sensehub-mosquitto            # after editing passwd/acl: reload without dropping clients
docker compose up -d --build backend             # only if MQTT_PASSWORD changed
```

To add another monitor (for example farm 1022), add a user to `gen-passwd.sh` and `.env`, and grant it
`topic readwrite farm/1022/#` in `config/acl`. The backend subscribes to `farm/+/#` and provisions a new
"Irrigation Monitor 1022" equipment row on its first valid message. You don't need to change any backend code.

## Device settings (farm 1021)

- Host `192.168.1.100`, port `1883`, TLS off
- Username `farm1021`, password = `MQTT_DEVICE_PASSWORD`
- Client id: `farm1021-monitor` (fixed and unique)
- Keepalive: 30 s
- LWT: topic `farm/1021/status`, payload `{"v":1,"state":"offline"}`, QoS 1, retained

## Ingest

The backend `services/MqttIngestService.js` writes to the equipment row, to `readings` (downsampled)
and to `irrigation_cycles`. Its read-only API:

- `GET /api/mqtt/health`
- `GET /api/mqtt/monitors`
- `GET /api/mqtt/monitors/:farmId`
- `GET /api/mqtt/irrigation-cycles?farm_id=&from=&to=&limit=&offset=`
